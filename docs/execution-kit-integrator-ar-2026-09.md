# مجموعة التنفيذ — منشور المُدمِج (المرحلة 3 + 4، جاهزة للتنفيذ)

الحالة: **تخطيط فقط من جهة CoreGuard** — CoreGuard لا ينفّذ أي شيء حي ولا يحمل
أي credential. هذه المجموعة **قابلة للتنفيذ صراحةً من قِبل طرفٍ يحمل حساب اختبار
(People's Court) حقيقي**. كل شيء مُجهَّز بحيث تكون الخطوات الحية الثلاث على بعد
«نطاق عمل موقع واحد» فقط.

وثائق مصاحبة:
`docs/phase3-credential-acquisition-plan-2026-09.md` (التخطيط + قائمة قرارات
المالك)، `docs/evidence-dossier-2026-09.md` (مصفوفة DRY-RUN المُتحقَّق منها +
خطوات L1–L3)، `docs/integration-surface-map-2026-09.md` (السطوح).

الرابط الخارجي الوحيد المستخدم في كل مكان:
https://github.com/EsLaM-X/coreguard/releases/tag/v0.6.0

## 1. ما هذا (تقديم من دقيقتين للمُدمِج)

CoreGuard هو طبقة تحقّق حتمية (deterministic) تفشل إغلاقًا (fail-closed) بين
*أدلة تنفيذ الوكيل* و*التحكيم*:

```
execution evidence → consent state → ADAL/1 dispute package → tribunal adapter → external award → authorized settlement
```

كل خطوة تعمل دون اتصال ومُثبَّتة بالبايت. أي تغيير بحرف واحد يُرفض عبر فحوص
SHA-256؛ أي نقص في الموافقة يبقى UNKNOWN؛ طبقة الأدلة لا تخترع حكمًا ولا تسويةً
ولا تكاملًا. المشروع يحمل **أداة جاهزة لاختبار حساب حقيقي (harness)** تبني
حزمة النقل وتُثبّتها وتعيد تشغيل بث webhooks مسجَّلًا بأمر واحد:

    npm run peoples-court:harness -- --case examples/delivery-fixture/pairs/dispute-package/reference-A

## 2. ماذا نحتاج من المُدمِج

1. **حامل credential لحساب اختبار (Partner API v2) من People's Court** (لخطوات
   L1 + L2) و**ن نقطة webhooks عامة** (لخطوة L3).
2. **توقيع نطاق صريح لكل خطوة** — يوقّع مالك المشروع نطاق هذه المجموعة، ويوقّع
   المُدمِج نفس النطاق. لا تفويض دائم.
3. **موافقة على تسجيل ما يعيده النظام الأساسي علنًا فقط** — ربط التأكيد
   (confirmation binding)، الحزمة المقبولة، البث المستلم — كـ fixture داخل
   المستودع مع مصدر وتجزئة التقاط.

## 3. الخطوات الثلاث (كل واحدة صغيرة، وكل واحدة تبعد بأمر واحد)

### L1 — منحة سلطة حية (live authority grant)

| | |
|---|---|
| من ينفّذ | credential الخاص بالمُدمِج يرسل منحة واحدة على سطح منح السلطة في Partner API v2 |
| ما يعود | ربط تأكيد النظام الأساسي (`actorId` / `principalId` + بيان مربوط بالتجزئة) |
| دور CoreGuard | مقارنة خريطته المرشَّحة `DERIVED` بتجزئة التأكيد؛ تسجيل التأكيد العام (المصدر + تجزئة الالتقاط) — CoreGuard لا «يؤكّد نفسه» أبدًا |
| معيار القبول | عودة التأكيد + تطابق بنيوي للتجزئة مع خريطتنا + تسجيله كـ fixture |

### L2 — `adjudication.prepare()` حي

| | |
|---|---|
| المدخل (جاهز دون اتصال) | `npm run peoples-court:harness ...` يُخرج `x402-prepare-packet.json` + `x402-packet-digest.json` — `idempotencyKey` حتمي من إصدار الحزمة المثبَّت |
| من ينفّذ | نفس الـcredential يرسل الحزمة المبنية على سطح x402 |
| معيار القبول | قبول الحزمة من النظام الحي؛ بقاء التجزئة التي ثبّتناها مطابقةً بايتًا ببايت |

### L3 — استقبال webhooks حي

| | |
|---|---|
| من ينفّذ | نقطة المُدمِج تستقبل بث at-least-once (حمولات `eventId`) |
| أداة CoreGuard | `webhook-consumer.mjs` يعيد تشغيل البث المسجَّل — إزالة تكرار `eventId` + مؤشر تسلسل + تعليق خارج النسق |
| معيار القبول | تقرير يعرض أعداد applied / duplicate / out-of-order + المؤشر، مطابقًا لدوالّ الاختبار دون اتصال |

## 4. ماذا ندّعي، خطوة بخطوة (صياغة صادقة)

| الخطوة | الادعاء الصادق بعد النجاح | ما لن ندّعيه |
|---|---|---|
| L1 | «سُجِّلت منحة سلطة حية مؤكَّدة من المنصة (مصدر + تجزئة)» | ليس: موافقة منصة، أو شراكة، أو سلطة تسوية |
| L2 | «قُبلت حزمة النقل التي ثبّتناها من سطح x402 الحي» | ليس: أن التحكيم جرى، أو أن حكمًا موجودًا |
| L3 | «أُعيد تشغيل بث webhooks مسجَّل بدوالّ إزالة التكرار وسلامة المؤشر» | ليس: وقوع أي تسوية أو escrow |

المصطلح ينتقل من **DRY-RUN** إلى *شريحة حية مسجَّلة، خطوة بخطوة*. لا شيء أوسع.

## 5. ما لن يحدث (ملزم، دون تغيير)

- لا تسوية، لا بث على شبكة رئيسية، لا نشر escrow — `CONDITIONAL NO-GO` الحاكمة؛
  يبقى `deployed:false` غير قابل للتغيير في الاختبار.
- لا يدخل أي credential إلى المستودع إطلاقًا — فقط *استجابات عامة مسجَّلة*
  كـ fixtures.
- لا ادعاء بتأييد أو شراكة أو تمويل أو «تكامل حي» يتجاوز الأحداث الثلاثة
  المسجَّلة أعلاه.

## 6. الجهد والأذونات

| الخطوة | الجهد | ماذا يُنفَّذ | البرمجيات |
|---|---|---|---|
| L1 | ≈30 دقيقة | إرسال API واحد بالـcredential + التقاط التأكيد | لا شيء |
| L2 | ≈15 دقيقة | الـharness دون اتصال → ثم إرسال حزمة واحدة بالـcredential | Node 18+ |
| L3 | ≈30 دقيقة | النقطة تستقبل البث → إعادة تشغيل عبر `webhook-consumer.mjs` | Node 18+ |

أوامر التشغيل (بلا مفاتيح خاصة، ولا شيء يعمل على جهاز مؤلف CoreGuard):

    npm run peoples-court:harness -- --case examples/delivery-fixture/pairs/dispute-package/reference-A
    node packages/peoples-court-adapter/cli-harness.mjs --case examples/delivery-fixture/pairs/dispute-package/reference-A --feed packages/peoples-court-adapter/examples/recorded-feed.json
