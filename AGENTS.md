# AGENTS.md — Operational Learnings for Future Sessions

Project: EslaM-X/coreguard (CoreGuard Gate 4.1 Assurance) — lessons from live sessions that are **not** obvious from code/docs alone. Keep entries 1–3 lines each; add to the most fitting section, don't restate what's already in README/docs.

## Environment & Tooling Quirks

- **PowerShell 5.1 mojibake generator**: any JSON written via PowerShell here (freeze records, reports) risks CP1252 mojibake of em-dashes (—) because PS reads .ps1 files without BOM as ANSI. It happened **twice** (freeze 4.2.4 + 4.2.6). Fix: regenerate/repair via a Node script (`node -e` or a .cjs), never via PS — encoding hygiene test will fail otherwise. Where unavoidable, write ASCII only (no em-dash) or use a Unicode escape.
- **`.gitattributes -text` is load-bearing**: three trees (`coreguard-assurance/**`, `coreguard-assurance-v4.2.2-remediation/**`, `legacy-quarantine/**`) are `-text` (no CRLF↔LF normalization) because freeze-record hashes are byte-exact. Any new hash-verified evidence tree must be added to `.gitattributes` **before** first commit or reviewer clones won't hash-match.
- **`git show HEAD:file` ≠ disk for uncommitted work**: when verifying hash freezes, always check the **committed tree** (via `git show`), not the working disk — uncommitted edits silently make a "clean clone" verification fail (cost a full session).
- **No BOM in generated JSON**: encoding hygiene test rejects BOM in all files except `.ps1` and `scripts/verify-live.json`. Writing UTF-8 with BOM via PS (`-Encoding UTF8`) fails the test; use Node or `-Encoding UTF8NoBOM`.
- **`node --test` accepts globs/dirs**: `node --test test/encoding/` may match nothing silently. Point at the test file itself or use `npm test`.
- **Adding a `packages/*` workspace requires a lockfile regen**: declare a new package and `npm ci` fails every job (Demos/Engine/DDE) with "Missing: @coreguard/x from lock file". Red runs 35478251772 (delivery) + 35490813895/823 (pricing) were this. Guard: `scripts/check-lock-sync.mjs` (runs in CI **before** `npm ci` and in `npm test` via `test/ci/`); fix = `npm install` at root + commit `package-lock.json`.
- **Multi-line plain `run:` scalars build ZERO jobs**: a `run:` value that is a plain (unquoted, non-block) scalar continuing on the next indented line makes the whole workflow unparseable — GitHub marks the run `failure` with no jobs/logs. Red run 35480761761 (commit 6c4ca1d) died this way. Always use `run: |`. Guard: `scripts/check-workflows.mjs` (CI + `test/ci/`).
- **The zero-jobs trap is not a one-off**: it struck 6 times — 5 runs on 09-11 (`5162c10`, `19e8e8f`, `3e9a289`, `95de625`, `37c8b3a`; culprit `console.error('receiptId mismatch: '...)` inside a plain `run:`) and `6c4ca1d` (`{ port: 0 }`). Same signature every time: run `failure`, **zero jobs**, no logs. Guard must run before any step that could touch sensitive YAML; see `docs/ci-postmortem-2026-09-20.md`.
- **Missing `package-lock.json` fails opaque inside `setup-node`**: with `cache: npm`, `actions/setup-node` dies with `##[error]Dependencies lock file is not found` BEFORE any guard placed after it can run (red run 34440426922 at `41ed0b4`, bootstrap era). Rule: the lockfile guard runs **before** setup-node (Engine/Demos/DDE), and `check-lock-sync.mjs` returns `no package-lock.json in repo root` rather than a raw ENOENT (class-H regression test in `test/ci/lock-sync.test.js`).
- **Bootstrap-era red classes are closed, not erased** (register in `docs/ci-postmortem-2026-09-20.md`): Node18/20 `node --test` quoted-glob `Could not find .../*.test.js` (fixed `164c77b`); WebCrypto global absent on Node18 → `node:crypto` (`6efd636`); python-pin `verifier-c: Dec-C-9 got 3.12.3, expected ^3.14` → `setup-python` 3.14 (`8a66816`); forge `Stack too deep` → `51a5069`. GitHub has no run-delete/rewrite API — don't promise "making them green"; document cause + fix + guard instead.
- **`unzip` is not installed on this Windows dev box**: the old `convert-zip.test.js` shelled out to `unzip` for member verification — 2 tests failed locally while Linux CI kept passing, so Windows-only failures hid inside a green suite. Rule: no test may depend on an external CLI that CI has but Windows lacks; ZIP verification is now in-process (EOCD scan + central-directory count + local-header walk + CRC-32 recheck + `inflateRawSync`), so local and CI see identical bits.
- **`node --test` summary uses non-ASCII glyphs — ASCII grep filters "find nothing"**: PASS/FAIL lines start with `✔`/`✖` and the summary with `ℹ` (tests/pass/fail). `Select-String "^(ok|not ok|...)"` over the pipe returns nothing even when tests ran and failed — "(no output)" is a filter miss, not a green run. Capture `node --test <file> *> out.txt` and read the file tail for the real counts.
- **The Pages-build race exists, and the median pusher is local tooling, not CI**: the Pages history alternates built/errored ("Page build failed") in 18–40s pairs. `chore(perf)` median commits (author `coreguard-trend-bot <noreply@coreguard.local`) land ~17s after a content push — for `d69a0fc` the DDE run started 02:04:11Z yet the median `15114d8` was committed 02:04:23Z, impossible for a workflow in `npm ci`; so a local process pushes medians on a timer. Guard: `scripts/pages-settle.mjs` (poll `pages/builds/latest`; only a settled build may be pushed over) — call it before ANY push that can trigger Pages, and the DDE trend step already does via `GH_TOKEN`.

## Hidden Relationships & Chain-of-Integrity

- **Freeze-record hash → any file edit invalidates it**: editing a file in `release/freeze/` scope (including README, H1-H8.md) invalidates its SHA-256 in `freeze-record-4.2.6.json`. Rule: after any content edit, re-pin the hash inside the freeze record (keep `frozenAtUtc` unchanged), then re-verify 49/49 from disk. Re-pin `commit` refs must point at a commit **on main's history** (after any rebase, re-point the ref before pushing — a ref to a rewritten commit hashes fine locally but is `COMMIT-MISSING` on CI).
- **Deleting docs still pinned in older freeze records breaks historical verification**: `freeze-record-4.2.5.json` pins hashes of `v4.2.5-closure/engine-semantics-contract.md` and `external-evidence-model.md`. If those files are ever deleted, 4.2.5 becomes unverifiable for those entries. Any deletion must be documented in the superseding record (currently a known gap).
- **`reviews-extra/` is external evidence (Option B model)**: the assurance cycle intentionally fails (`BLOCKED exit 1`, `INV-001 fail-closed`) on a clean clone because `reviews-extra/` (in `D:\KOSSASHI\CORE DAO\reviews-extra\`) is deliberately outside the repo. Do not "fix" the BLOCKED; it's documented fail-closed behavior. A clean clone still can run SelfTest/NegativeSuite — only the standard run needs external evidence.
- **SelfTest vs standard-run scope**: SelfTest (21 checks) and NegativeSuite (16 scenarios) are environment-independent and always runnable from repo alone; the "standard run" (`-OutDir release`) rewrites frozen outputs (`selftest.tap`, `negative-tests.json`, `verification-report.json`) — don't run it casually over frozen artifacts; verify determinism by re-running into a separate OutDir and diffing.
- **Legacy quarantine**: all legacy broadcast/private-key scripts live under `legacy-quarantine/2026-09-18-v4.2.2/` and stay byte-identical to their originals (proof via `orig|quarantine` pairs in the manifest). They are outside the LEG-001 scan roots by design; do not reintroduce them into `scripts/`.
- **Manifest vs freeze-record**: `release/manifest.json` pins a subset of files (engine outputs); `release/freeze/freeze-record-*.json` pins everything (release + quarantine). The internal manifest can lag the engine version — check it against current engine outputs before trusting a "current" state claim.

- [C1] **Multi-line plain scalar with `": "` kills the whole workflow (zero jobs)**: a `run:` value written as a plain (non-block) multi-line YAML scalar containing a JS literal like `console.error('health check failed: ...')` — the `": "` inside a plain scalar is unparseable → GitHub marks the run `failure` with **zero jobs built**. That zero-jobs conclusion IS the signature of an unparseable workflow file (not a failing step). Fix: any multi-line `run:` must be a real block scalar (`run: |` on its own line). Trap within the trap: a string-matching "validator" whose `||` fallback jumped to a fake parser reported PASS — only a real YAML parser or GitHub itself building the job proves the file parses (cost a push + a red run). Now enforced mechanically: `test/ci/workflow-yaml-contract.test.js` parses every `.github/workflows` file and the composite action with the real `yaml` parser (dev dep) plus an Actions schema walk — an unparseable or schema-deviant file fails the push locally with file+line naming, before GitHub ever sees it. Runs inside `npm run prepush` too (scripts/pre-push-check.mjs), the mechanical pre-push checklist built from the YAML/workflow lessons: workflows-parse [C1] · freeze-integrity [C2] · pin-eol-cover [C3] · no-skip-ci (the skip-token vortex) · repin-reachable (the rebase rewrite trap) · remote-fresh (the bot race, with the autostash remedy named).
- [C2] **Commit-anchored verification (4.2.6+)**: `validate-freeze.mjs` hashes `git show <gitCommit>:<path>` blobs, not disk bytes. Disk mode (`--disk`) is triage-only, prints "not evidence". Records without `gitCommit` fail COMMIT-UNANCHORED (historical included — correct). Editing a file whose bytes exist only in a future commit requires a **two-phase re-anchor**: commit phase 1, then point `gitCommit`/`postCommitRePins` at that hash in phase 2. Release entries are platform-dir relative; quarantine entries repo-root relative; repo-root files outside the platform dir use `../` prefixes (stripped by `treePath`/`repoRelPath` — the honesty test must mirror this or bare-name pins hash the wrong file).
- [C3] **`git show HEAD:file` ≠ disk ≠ fresh-clone disk**: a pinned file outside every `-text` rule in `.gitattributes` is silently CRLF-rewritten on ANY fresh clone when `core.autocrlf=true` is set (system default on Windows) — the main working tree can hold LF bytes while a reviewer's pristine clone drifts and fails `--disk`. Always prove "clean-clone" claims from an actual fresh clone/`git -c core.autocrlf=false clone`, not from the dev disk. Any file newly pinned in a freeze record (including `../docs/…` — root-level pins outside the three `-text` trees) must be added to `.gitattributes` **and** the RC manifest must be rebuilt from a pristine `autocrlf=false` checkout (`scripts/build-rc-manifest.mjs` reads the disk, so generating on an autocrlf machine pins CRLF hashes that blobs don't match).
- [C4] **Bilingual dashboard i18n architecture (the pattern that works)**: three defects killed the first attempt — (1) swapping only the first text node left Arabic tails around inline children (`.ltr`, badges); (2) the resolver `L()` was scoped inside an IIFE that ran after the views' initial render → `L is not defined` + dead toggle; (3) attr swaps targeted markup markers that didn't exist. The working design: **hoisted global `L()` prelude** at script top reading live language from `window.cgLang` at call time; **full `innerHTML` swap** per `[data-i18n]` element (text + inline children together, no tails); **views re-render on a `cg41:lang` CustomEvent**; dynamic strings stored as `{ar,en}` pairs resolved through `L()`; attrs applied by unique selectors, not markers. Dictionary generated by structural pairing (637/637 nodes) against the EN sister — never hand-maintained.
- [C5] **i18n dictionary generation trap**: naive text-node pairing undercounts mixed-content elements; generate the dict by lockstep DOM-walk pairing (tag+index paths, EN `printhead` subtree dropped first) and capture full `innerHTML` per element. Verify coverage honestly: every Arabic run in the raw body must land in exactly one slot, and the EN side must contain zero Arabic chars.
- [C6] **Async render loops in review/verification UI**: the classic bug is `if (stateA !== stateB) render()` inside a promise `.then` — inverts to a permanent re-render loop. Fix: capture `target` state at render start, apply with `target` (not live state), and only re-render if live state differs from target. Cost a session to debug in the visual explainer.
- [C7] **postCommitRePins honesty discipline**: every re-pin entry must be honest vs its declared commit — the test catches duplicate/stale entries for the same file (a real CI failure, run 35398048308). Never leave superseded re-pin entries behind. The contract tests read the expected PASS count from the record itself, never hardcoded literals — a frozen `46/46` breaks on every honest pin addition.
- [C8] **Freeze-record hash mismatch after PS write**: the hash pinning mismatch looks like "file changed after freeze" — usually it's actually mojibake corruption of a field (em-dash) that changed the bytes. Check the file content for mojibake-style high-byte sequences (C3 xx / C2 xx patterns around em-dash positions) before assuming drift. Never quote a mojibake sample literally in AGENTS.md/docs — the hygiene scanner flags the example itself.
- [C9] **"npm test 696/696 PASS" is not a green light for assurance claims**: encoding-hygiene tests are inside the 696; mojibake failures appear there first. If CI is red on encoding, suspect the most recently generated JSON (written by PS) before suspecting code.
- [C10] **Resolve pin paths before declaring a freeze violation**: record paths are relative to the record's own directory — `README.md` there pins the *platform* README; the repo-root README would be `../README.md` (absent ⇒ not pinned). A session nearly triggered an unnecessary re-pin cycle because a naive `pinned.includes(changedFile)` scan matched the platform pin against a root-README edit. Normalize paths with `treePath`/`repoRelPath` semantics (or diff against the anchor with the same normalization) before starting any re-pin.
- [C11] **NegativeSuite premise path**: `-Manifest` is resolved via `Test-Path -LiteralPath` from the CWD — run the suite from the platform dir, not the repo root, or the manifest premise becomes PRECONDITION_FAILURE and fails the whole cycle (correctly). It rewrites frozen `negative-tests.json`; determinism proof = git diff empty after rerun.
- [C12] **Stale GREEN: session-persisted candidates mutate between verdict and use (read scope consent defensively)**: a candidate directory that survives across steps or sessions is a mutable surface — the consent/disclosure scope (and any record) can change between the gate's GREEN verdict and the moment a consumer (e.g. `convert-to-fixture.mjs`) reads the files, so a **remembered** GREEN from an earlier step would package records the gate never saw. Defensive reading: a verdict binds to exact bytes (pins), and every consumer re-runs the gate on the same tree it reads — never trust a verdict carried across steps. The intake pipeline does exactly this: `convert-to-fixture.mjs` re-runs the gate as its first act on the directory it then reads, and re-verifies pins against disk after write — the reason the pipeline never converts on stale consent.
- [C13] **Hand-built ZIP needs unix external attrs or Linux extracts mode-0000**: writing only the local headers/CRC leaves the central-directory external-attributes field zero; `made-by: unix (0x031e)` makes Info-ZIP derive the mode from it → every extracted file is 0000 and reads EACCES on Linux (red CI run on `1a49d16`). Windows masks this entirely — always write `(0o100644 << 16)` at offset 38 when made-by is unix. The archive's determinism tests stay green on Windows either way, so only a Linux runner catches it.
- [C14] **`process.exit()` right after a large piped stdout report truncates the tail on Linux**: stdout writes to a pipe are asynchronous — exit before the queue drains silently drops whatever is still buffered (the new reviewer-table contract on `09b4aae` lost exactly the `perf` and `verdict` lines from a ~300-line runner report; local Windows runs are synchronous and always green, so only Linux CI showed it). Rule: CLIs that print a report set `process.exitCode` and let the event loop drain — reserve `process.exit()` for usage-error exits where the (tiny) stderr message going missing is harmless. The runner now uses `process.exitCode` in both its text and JSON branches, with the drain rule commented at each site.
- [C15] **`node -e` assumes CJS when no package.json governs the eval cwd**: the eval script's module type comes from the nearest package.json to the CURRENT DIRECTORY, not to the repo — run `node -e "import …"` (or a `.mjs`-style dynamic import) from a Linux path outside the project (or an unmanaged temp dir) and Node evaluates as CJS, where a top-level `import` is a SyntaxError; Windows sessions in this repo ran from the checkout (package.json with `"type": "module"` governs) so the same snippet worked locally. Rule: in `node -e`, never rely on ambient module type — use `node --input-type=module -e` for ESM snippets or `require()` for CJS, and always pass an explicit cwd inside the repo. Determinism holds either way: the module-type decision is byte-certain from disk state, so the same snippet is either green or red on a given machine — it never flips between.
- [C16] **Parallel test files that re-generate the same live fixture in place race each other**: two suites both calling the fixture generator against the shared `examples/delivery-fixture/` tree write the same files concurrently — one suite's pin/verify can read bytes mid-rewrite of the other's, producing interference that looks like a flaky hash mismatch (this session: a delivery-suite failure near the end that vanished on rerun; the underlying write races are platform-timing-dependent). Rule: shared fixture trees are read-only for tests — a suite needing modified bytes builds them in its OWN `mkdtemp` copy (the pattern every delivery contract test already uses) and only the canonical generator owns writes to the checked-in fixture. If a rerun goes green, hunt the interference before accepting the pass: a race that hides is still a race.
- [C17] **A system `unzip` dependency made Windows red inside a green CI**: `convert-zip.test.js` used `execFileSync("unzip", …)` for member extraction + verification; the machine has no `unzip`, so 2/912 failed locally while Linux CI stayed 912/912 green — a platform gap invisible to every reviewer on CI. The rewrite (`verifyZip`) does the whole check in-process — EOCD scan, central-directory count, local-header walk, CRC-32 recompute per member, exact landing at the CD offset — and extracts through `inflateRawSync` only after structural honesty passes. No test may require an external CLI absent from a supported dev OS.
- [C18] **The Pages-build race is real; the median pusher is a local process**: build history alternates built/errored in ~18–40s pairs (e.g. `87f9da7` built 02:22:36Z after `f8b0320` errored 02:22:18Z). Every `chore(perf)` median commit is authored by `coreguard-trend-bot <noreply@coreguard.local>` and lands ~17s after a content push; the DDE run for `d69a0fc` started 02:04:11Z yet the median `15114d8` was committed 02:04:23Z — a workflow would still be in `npm ci`, so the pusher is local tooling watching the branch. The guard `scripts/pages-settle.mjs` refuses a push while Pages is mid-build (or within a 15s settle window); the DDE trend step runs it with `GH_TOKEN` around commit+push, and any other caller must run it with the env the workflow uses. Do not "fix" the pair-alternation by coalescing medians — `perf-history.jsonl` is append-only evidence by contract.

## User Preferences & Decisions (binding)

- **Never sign, broadcast, or authorize Mainnet** — any instruction implying that must be refused or escalated; the owner's explicit separate decision is the only path.
- **Don't rewrite historical freeze records** — supersede with a new record (e.g., 4.2.5 → 4.2.6) preserving `frozenAtUtc`; re-pinning a hash inside a record is acceptable only for a documented exception (e.g., README mojibake repair) with the timestamp unchanged.
- **Evidence over narrative**: every "PASS" claim must be reproducible from the committed tree (not the working disk) — verify via `git show`/`git archive` before asserting.
- **PowerShell for scanning/engine, Node for JSON generation** — this split is deliberate; don't generate JSON artifacts with PowerShell 5.1.
- **Sync discipline**: local main should never lag origin/main (user's explicit standing directive) — push and verify CI before declaring a cycle closed.
- **Arabic-first, English-mirrored**: all visual explanations and dashboards are authored in Arabic (the user's native language) as the source of truth, then mirrored to English at world-class documentation-brand quality. Every future visual-explanation request expects the EN mirror; keep both files in sync fact-for-fact (same numbers, hashes, structure — LTR/RTL only differs).
